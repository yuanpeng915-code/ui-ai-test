## 笔记编写规范

每个模块笔记包含以下章节：

1. **已知坑位** — 探索/沉淀中踩过的坑，含问题现象、根因、解决方案
2. **业务逻辑** — 该模块页面的 UI 特征（框架组件、特殊控件）

## 更新规则

- 每次沉淀新功能或踩坑后，追加到对应模块笔记
- 用户纠正错误后，**必须**先清理相关历史内容，再将纠正笔记写入
- 笔记用中文，简洁为主，不写废话
